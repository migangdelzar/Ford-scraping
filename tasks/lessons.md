# Lessons

- Failure mode: migration-backed read-view tests passed on a fresh database while an already-migrated catalog lacked parity views because the changes were edited into applied migration 022. Detection: restored-snapshot SQL failed with `relation ford_read.vehicle_facts_v2 does not exist`. Prevention: keep shipped migrations immutable and test each forward migration against both a clean database and a restored database whose ledger already includes the prior migration.

- Failure mode: integration tests inherited `DATABASE_URL` and truncated live Ford catalog tables, destroying normalized specifications and features while raw pages remained. Detection: destructive SQL in integration setup and catalog counts dropping to zero. Prevention: integration tests must use only a dedicated database whose name ends in `_test`; never fall back to `DATABASE_URL`, and keep a restorable `pg_dump` backup before database-mutating test runs.
- Failure mode: Docker commands used the native `default` context while Colima `default` was running on its profile socket. Detection: `docker context show` returned `default`, while `colima status --profile default` exposed `.colima/default/docker.sock`. Prevention: verify the active context/socket before every Docker operation; use the explicit profile socket when context activation is ambiguous.
- Failure mode: importing the 6.99 GB Ollama image filled host storage and left partial containerd metadata. Detection: host free space fell below 200 MB and Docker reported `input/output error`. Prevention: check host free space before image import; prefer the already-installed native Ollama model or a verified smaller image, and remove only the failed image artifacts.
- Failure mode: a local model sent nullable optional financing filters and routed financing-only questions to the combined vehicle tool. Prevention: make optional filters nullable at the MCP boundary, strip nulls before service calls, and state routing conditions explicitly in the system prompt.
- Failure mode: a compact combined result exposed vehicle and offer prices with the same label, so the model omitted one. Prevention: provide a copy-ready summary and require the vehicle price, offer cash price, monthly payment, and validity disclosure as separate facts.
- Failure mode: semantic vehicle search returned a nearby model for an exact combined request, and a negative answer was mistaken for an availability claim. Prevention: enforce exact model/year selection in the composite tool and make the scorer recognize explicit negative wording.
- Failure mode: comparison payloads exposed omission counts and feature arrays that caused the local model to enumerate data until its output was truncated. Prevention: return comparison prices and a small specification subset only; require source links only when a source exists.
- Failure mode: the local model sent a singular `model`/`modelYear` payload to a two-vehicle comparison tool. Prevention: treat that malformed shape as an empty comparison result so the answer stays truthful and the MCP session remains usable.
- Failure mode: the local model copied a source field name instead of its URL and expanded long equipment lists. Prevention: expose a copy-friendly source URL alias and cap vehicle detail and missing-name arrays at three items.
- Failure mode: the model said offers did not meet a budget without explicitly stating that they exceeded it. Prevention: require the phrases “exceden el presupuesto” or “por encima del presupuesto” when returned prices are over budget.
- Failure mode: financing filters sent at the top level were silently discarded because the tool only accepted a nested `filters` object, allowing unrelated offers into a result. Prevention: accept and normalize both argument layouts, then enforce requested model/year against each returned offer.
- Failure mode: after getting an empty promotion result and populated finance results, the model repeated the finance tool with `offerType: promotion` and described finance plans as promotions. Prevention: instruct it to call each category once, treat empty promotion results as authoritative, and label returned finance plans only as financing.
- Failure mode: restarting the MCP was treated as sufficient while its PostgreSQL dependency was unavailable; HTTP initialize succeeded but catalog tools could not query. Prevention: verify the DB and execute a real authenticated tool call after every local MCP restart.
- Failure mode: Ford model URLs use two-digit years, and non-rendered empty parses erased valid specifications; currency `00/100` was also parsed as a zero-month term. Prevention: parse year suffixes from model URLs, preserve stored details when extraction returns no values, and only parse terms with explicit “meses” wording.
- Failure mode: generic “sujeto a análisis de crédito” text classified every card from `/Promociones/` as financing. Prevention: let the source section determine offer category; use the financing page/API for financing plans and promotions page cards for promotions.
- Failure mode: removing query parameters only from MCP presentation left color selectors in the crawl queue and stored `pages`/`page_links` rows, allowing later results to reintroduce them. Prevention: normalize URLs at crawl and link-extraction boundaries, clean existing rows in a guarded migration, and assert live DB results after migration.
- Failure mode: a synthetic multi-turn LLM eval left a malformed tool-call message without a matching tool result, causing every later hop in that conversation to fail; its URL checker also inspected only the current turn and reported false positives. Prevention: always close each tool-call ID with a result (including parse errors), track trusted URLs across the full conversation, and record truncation per model response rather than per conversation.

- Failure mode: Node sync summary was treated as success even when page/embedding failures were counted. Detection: CLI returned exit status 0 despite nonzero `pagesFailed`/`embeddingFailures`, which would let scheduled CI report a false green. Prevention: make the CLI exit contract fail on either partial-failure counter and verify it with focused CLI tests plus a disposable DB run.
- Failure mode: a macOS source archive included `._*` AppleDouble files, and the migration runner tried to execute one as SQL (`invalid message format`). Detection: PostgreSQL reported protocol parse failure during the disposable integration run. Prevention: create archives with `COPYFILE_DISABLE=1`, inspect/filter archive metadata before transfer, and run migrations only from the clean packaged source tree.

- Failure mode: a fresh Node PostgreSQL integration run started against a blank test database and failed because other test files queried tables before the catalog-read-view test's concurrent migration setup completed. Detection: `schema "ford" does not exist` and empty `information_schema` results in non-catalog integration files. Prevention: create a disposable database ending in `_test`, run `DATABASE_URL=<test-url> npm run migrate` first, then run the complete suite with `FORD_TEST_DATABASE_URL=<same-test-url> npm run test:integration`; never point either command at a production/local working database.
- Failure mode: contract tests encoded retired MCP workflow wiring and failed after the approved runtime ownership change. Detection: deployment tests still required MCP secrets/remote MCP despite the intended local catalog adapter. Prevention: update release contract assertions alongside the approved topology change and verify them against the actual workflow and runtime configuration.
- Failure mode: Colima exposed a mapped PostgreSQL port but the host could not connect to it. Detection: mapped localhost port refused connections before PostgreSQL protocol negotiation. Prevention: run the client and disposable DB on the same isolated Docker network; distinguish host port-forwarding failures from DB/test failures and clean up only test-owned containers/networks.
- Failure mode: a broad repository secret search included the ignored deployment credential file and printed secret values into diagnostic output. Prevention: never run generic content search over credential/config directories; inspect tracked templates only, and use a parser that emits key names/presence metadata without values for local secret inventories.
