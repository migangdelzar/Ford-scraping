# MCP LLM 100-flow evaluation — 2026-09-27

Model: `qwen2.5:3b` (Ollama), temperature 0. Run: `npm run eval:mcp:llm -- --start=0 --flows=100`.

The first complete run after the prompt and MCP guidance changes completed all 100 flows: 78 passed, 22 failed. The detailed per-flow output is in the ignored local artifact `eval-results/llm-100-final.stderr`; it is not committed because evaluation logs contain complete generated answers.

Failure counts (one flow can have more than one code):

- 16 `missing_tool:search_offers` after the model called `list_promotions` and then stopped. This is the dominant model tool-sequencing failure.
- 3 `missing_vehicle_result_detail` in combined vehicle and financing responses.
- 2 missing tool calls with no final answer; one also ended with `done_reason=length`.
- 1 excessive-length answer.
- 1 comparison request failed because the requested catalog model/year (`EDGE 2026`) was not found.
- 1 missing financing validity disclosure.
- 1 missing budget disclosure.

This run is a diagnostic of the LLM-driven system, not a passing release gate. It confirms that the prompt alone does not make Qwen 2.5 3B reliably complete multi-tool sequences. The later recovery change keeps those model omissions visible in a separate metric; the baseline result remains unchanged and rerun all 100 after further prompt, orchestration, or model changes.

## Follow-up: recover missing category searches without changing tool choice

The evaluator now preserves the full original tool list and lets the model attempt the request first. If a scenario requires both promotions and financing and the model ends its response without running one category search, the evaluator calls only the missing search, supplies that result to the model, and requests a final answer. It does not repeat a category search already called by the model. Reports separate `calledTools` (model choices), `executedTools` (model plus recovery calls), and `modelToolUseFailures` from end-to-end response failures.

Focused Ollama verification for flow 4 passed after this change. Qwen itself called `list_promotions` and `search_offers`; the answer kept promotions and financing separate and disclosed unknown validity. This checks the combined flow, but did not exercise fallback because the model chose both tools on that run. The attempted full rerun was stopped after two flows because local inference was progressing too slowly; there is no post-change 100-flow score yet.

The flow set is generated by `createScenario` in `scripts/evaluate-mcp-llm-flows.mjs`; it covers combined vehicle/financing, exact vehicle specs and provenance, comparisons, promotions plus financing, financing-only searches, and catalog status.
